# define-err platform notes

What each feature and target gives you. MSRV is 1.81, the first release with `core::error::Error`. Edition 2021.

## Features

| Features | Gives you |
|---|---|
| `default-features = false` | `core` only: every macro, every type except `ErrorRecord`, and the facade |
| `alloc` | adds `ErrorRecord`, boxed `dyn Error` sources, `set_boxed_reporter` |
| `std` (default) | adds `alloc`, `ErrorInfo` and `Category::from_io_kind` for `std::io::Error`, and the facade's reentrancy guard and panic isolation |
| `testing` | adds `std`, `testing::capture`, and `CaptureReporter` |

Features only add. Code generated by `define_errors!` contains no `cfg(feature)`, so a type compiles the same in every mode.

## Atomics

The facade needs compare-and-swap on 32 bits (`target_has_atomic = "32"`). The control word and each `warn!` site are `AtomicU32`. The `warn()` table uses `AtomicU64` keys, or `AtomicU32` keys on a target without 64-bit atomics, where a collision is more likely.

On a target without compare-and-swap, such as `thumbv6m-none-eabi`, no slot can be claimed safely, so the facade is compiled out. `set_reporter`, `set_boxed_reporter`, and `set_creation_hook` do not exist, every verb is an empty function, and the macros evaluate nothing. Library code that reports compiles unchanged. A racy `unsafe` installer, as in `log`, is deliberately not offered.

## Panics

| Build | A panic in `receive`, or in an error's `description()`, during a verb |
|---|---|
| `std`, `panic = "unwind"` | caught and counted in `stats().reporter_panics`; the verb returns |
| `std`, `panic = "abort"` | aborts the process: nothing can catch it |
| no `std` | follows your panic handler: the reporter must not panic |

The same table applies to reentrancy, except that it does not depend on the panic strategy: with `std` a verb called inside `receive` is dropped and counted, and without `std` the reporter must not call a verb.

No function in this crate panics at run time, on any of these.

## Thread-local storage

With `std`, the guard uses one `const`-initialised thread-local `Cell<bool>`. It does not allocate and has no destructor.

## Memory

| Item | Size |
|---|---|
| control word | 4 bytes |
| kinds mask | 8 bytes |
| reporter slot | a reference and a location |
| `warn()` table | 4 KiB, static, or 2 KiB with 32-bit keys |
| a `warn!` site | 4 bytes, static |

Nothing in the facade allocates. `ErrorRecord` allocates and is bounded by `RecordLimits`; `docs/PERFORMANCE.md` lists the counts.

## 32-bit targets

`Code` is a `u64` on every target, so codes and probes do not change between 32-bit and 64-bit builds. Facade counters in `stats()` are `u64` in the API and may wrap at 32 bits on a 32-bit target, which affects only the counts.

## Probe stability across versions

Two versions of this crate in one process each have their own facade slot, and read each other's probes. An application with two major versions of `define-err` needs a reporter installed in each. Cargo's unification makes this rare within one major version, where there is one slot.
