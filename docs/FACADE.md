# The reporting facade

How a library reports and how an application listens. The signatures are in [`API.md`](./API.md#reporting-facade); this file is the contract around them.

Any crate calls the verbs. The application installs one [`Reporter`](./API.md#reporter) at start-up. With nothing installed, a verb is one atomic load and returns, so a library can report freely without knowing whether anyone listens.

## What can never be observed

Errors are values; Rust has no throw event. The facade sees an error only when code calls one of its verbs. It cannot see an error discarded with `let _ =`, `.ok()`, or `unwrap_or`, or a typed error that is built and never reported. Building an error generated by `define_errors!` runs no code at all.

## Installing

Install first thing in `main`, before any library code runs, and treat a failure as a fatal boot error.

```rust
static REPORTER: MyReporter = MyReporter;

fn main() {
    if let Err(err) = define_err::set_reporter(&REPORTER) {
        eprintln!("{err}");                // names where the other reporter was installed
        std::process::exit(70);
    }
    // ...
}
```

The slot is write-once and is never replaced. That is a security property: a dependency that installs first would otherwise see every error the application reports, or silence them. The failure names the file and line of the winner, and `define_err::reporter_installed_at()` answers the same question at any time, for audits.

Warnings raised before installation are not lost: they do not use up their call site, and are delivered the first time they happen afterwards.

## The reporter contract

| Rule | Why |
|---|---|
| `receive` returns in microseconds and never blocks on I/O. | It runs on the caller's thread, in the caller's error path. Queue instead, as the error service does. |
| It may be called from any thread at once. | `Reporter` is `Send + Sync`, and one reporter serves every thread. |
| It must not assume one call per error. | A report and a later warning about the same error are two events. |
| It keeps nothing borrowed from the event. | `Event` lives on the caller's stack for the length of the call. Copy what you need, or build an [`ErrorRecord`](./API.md#errorrecord), which is owned, bounded, and `Send + Sync`. |
| With `std`: calling a verb from inside `receive` is safe. | The nested event is dropped and counted in `stats().reentrant_dropped`. |
| With `std`: a panic inside `receive` is safe. | It is caught and counted in `stats().reporter_panics`. A payload that panics when dropped is caught and counted too. So is a panic in a reported error's own `description()`, which a verb calls to read the probe. |
| Without `std`: `receive` must not call a verb and must not panic. | Neither guard exists: there is no thread-local and no `catch_unwind`. |
| Under `panic = "abort"`: a panic in `receive` aborts. | Nothing can catch it. |

## Choosing a verb

| Verb | When | Kinds | Severity | Once per site |
|---|---|---|---|---|
| `report(&err)` | an error reached a boundary (a request handler, a job runner, `main`) | from the error | from the error | no |
| `report_with(&err, severity, kinds)` | the caller knows better than the definition | as given | as given | no |
| `report_record(&record)` | a dynamic error type has more than a `source()` chain can carry | from the record | from the record | no |
| `notice("...")`, `notice!` | something worth recording, below a warning | `NOTICE` | `NOTICE` | no |
| `warn("...")`, `warn!` | something is wrong but work continues | `WARNING` | `WARNING` | yes |
| `trigger(kinds, "...")`, `trigger!` | raise a named condition on purpose | `TRIGGER` plus the given kinds | `WARNING` | no |
| `deprecated("...")`, `deprecated!` | a configuration key, protocol field, or endpoint is on its way out | `DEPRECATED`, `WARNING` | `WARNING` | yes |
| `soft(err)` | a warning today that a strict deployment refuses | `WARNING` plus the error's | `WARNING` | no |

Report at boundaries, not at every `?`: reporting never changes control flow, so a chain of `?` that reports at each step reports the same error many times.

Every function is `#[track_caller]` and every macro expands at the call site, so the event's location is the caller's file, line, and column. A `#[track_caller]` helper that calls a verb reports where the helper was called.

The macros evaluate their arguments only when the event could be delivered: with nothing installed, or for a `warn!` site that has fired, the arguments are not touched.

## Once per call site

- **The macros** keep one flag at each call site: exact, for any number of sites. A site inside a generic function is one site for every instantiation.
- **The functions** cannot own a static per call site, so they keep a fixed, lock-free table of 512 sites, keyed by a hash of the caller's file, line, and column. Past 512 distinct sites, the extra sites deliver every time and `stats().site_table_overflow` counts them: a warning is never lost to the table. A false match needs a 64-bit hash collision among at most 512 sites (below 10^-14). Targets without 64-bit atomics use 32-bit hashes (about 3 x 10^-5, across all 512).

A site is marked only when the warning would reach the reporter. A warning filtered out by the severity or kinds filter, ignored by the mode, or raised before installation keeps its one delivery for later.

## Filters

Three process-wide settings, for the application or the error service. Per-listener filtering, storm control, and per-code policy belong to the error service.

| Setting | Default | Effect |
|---|---|---|
| `set_warn_mode` | `Once` | `Once`, `Always` (every warning; switching back keeps the sites that fired), `Ignore` (warnings dropped; `report`, `notice`, and `trigger` unaffected), `Error` (as `Once`, and `soft` returns `Err`) |
| `set_min_severity` | `None` | events below it are dropped before anything is formatted |
| `set_kinds_mask` | `Kinds::ALL` | events with no kind in the mask are dropped; `ALL` passes everything, an event with no kinds included |

A report has to read the error's probe to learn its severity, so a filtered `report` costs the probe read. `is_installed()` is the one-load check for skipping expensive preparation.

## Records and the creation hook

`ErrorRecord::from_event(event)` is what a reporter calls when it keeps anything. Every part is bounded by `RecordLimits`, the public message comes from the variant's `#[public]` or the category's default and never from any `Display`, and a `Secret<T>` field stays `[redacted]` in the chain.

The creation hook is a second write-once slot, for an observer that adds scope data (a request id, a tenant) **when a dynamic error is created**. Only dynamic-error libraries call it. Errors generated by `define_errors!` never do, because building a typed error has no side effects. The caller of the hook owns its guards.

## Targets without compare-and-swap

On `thumbv6m-none-eabi` and similar targets no slot can be claimed safely, so the facade is compiled out: `set_reporter`, `set_boxed_reporter`, and `set_creation_hook` do not exist, every verb returns at once, and the settings stay at their defaults. Library code that reports compiles unchanged, which [`examples/no_std`](../examples/no_std/src/lib.rs) shows and CI builds.

## Testing code that reports

With the `testing` feature, `testing::capture` runs a closure and returns every event delivered on that thread, so tests running in parallel never see each other's events. If a different reporter is installed it returns `Err` instead of running the closure: an empty list must never pass as the real one. Warn sites are process-wide, so a site that fired in one test stays silent in the next; give each test its own call site.

## How it is built

One packed `AtomicU32` holds the state of both slots, the warn mode, and the minimum severity, so a verb needs one `Acquire` load. A slot is claimed by a compare-exchange, written once, and published by a `Release` store; a reader reaches it only through a word from an `Acquire` load that says ready. This is the `log` crate's `set_logger` pattern. `src/facade/slot.rs` is the only `unsafe` code in the crate. `tests/loom.rs` models every interleaving of the slot, the settings, the site flags, and the table, and Miri runs the test suite.
