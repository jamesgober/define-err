# define-err v0.3.0 - Core

**thiserror parity, without a proc macro.** v0.3.0 shipped `define_errors!`: one line per variant, and the macro writes the enum, `Debug`, `Display`, `core::error::Error` with `source()`, and the `From` conversions, the same code thiserror generates and a person would write by hand. It also shipped `Secret<T>`, `Location`, and the first methods of `ErrorInfo`.

## What is define-err?

<strong>define-err</strong> is how a Rust library says what its errors are, with no proc macro, no build dependency, and no run-time cost. Optional stable codes, severity, categories, kind masks, a code catalog, and a reporting facade follow in the next releases. It is `no_std` and has no dependencies.

```rust
use define_err::prelude::*;

define_errors! {
    pub enum PageError {
        NotFound { page: u64 } => "page {page} not found",
        ShortRead(page: u64, got: usize) => "short read on page {page}: got {got} bytes",
        Io(#[from] source: std::io::Error) => "page file i/o failed",
    }
}
```

## What's in 0.3.0

- **`define_errors!`.** Enums and structs, braced, tuple, and unit. Messages after `=>` reference fields by name with any format spec; extra arguments go in parentheses; `=> transparent` forwards to the only field. `#[source]`, `#[from]`, or a field named `source` is the source, including `Option<E>` and boxed `dyn Error`. `#[from]` generates a `#[track_caller]` `From`, so a `#[location]` field records the line of the `?`. Enums are `#[non_exhaustive]` unless marked `#[exhaustive]`; `Debug` is derived unless `#[manual_debug]`. Doc comments and lint attributes pass through.
- **thiserror parity, checked.** A conformance suite writes every case both ways and requires byte-identical `Display` output and `source()` chains against thiserror 2. A pilot rewrite of page-db's error type passed page-db's whole test suite, clippy, and rustdoc without any other change.
- **Large enums.** An enum written in the canonical form (doc comments first, a field marker right before the field name, tuple fields named) is parsed by one non-recursive macro arm, so 500 variants compile at the default `recursion_limit`; a test proves it. Other forms take a slower path that costs one macro step per variant.
- **No cost.** Construction, `Display`, `source()`, `ErrorInfo`, `From`, and `Secret` formatting allocate nothing (a counting allocator checks it). Generated types have the same size as hand-written and thiserror enums. Measured with criterion on an AMD Ryzen 9 9950X3D under Windows 11 and Rust 1.99, with other build sessions running on the machine: `Display` of a two-field variant took 22.5 ns with define-err, 22.3 ns with thiserror, and 23.4 ns hand-written; construction with `source()` took 0.33 ns for all three. The differences are noise.
- **`Secret<T>`.** Prints `[redacted]` under `Display` and `Debug` with any flags; width, fill, and alignment are honoured, precision cannot cut the word. No `Deref` and no `PartialEq`, checked by compile-fail tests.
- **`ErrorInfo`** with `location()` and `type_name()` (`"Type::Variant"`), **`Location`**, and **`here()`**.
- **Compile errors that say what to do**: unknown attributes list the valid ones; two sources, two locations, `#[from]` with extra fields, `transparent` without exactly one field, a missing message, and a source field that is not an error each get one sentence naming the problem and the fix. 23 compile-fail tests pin the messages.
- **Works everywhere the crate does**: generated code compiles without the prelude, next to user types named `Error`, `Result`, `Option`, `Box`, or `Display`, in edition 2021 and 2024 crates, and with `--no-default-features` (boxed sources need `alloc`).

## What's next

`0.4.0` adds stable error codes (`DB-0042`) with a compile-time catalog, severity, categories with their HTTP, gRPC, and exit-code tables, kind masks, public messages, retry advice, the rest of `ErrorInfo`, and the identity probe that lets other libraries read codes through `&dyn Error`.
