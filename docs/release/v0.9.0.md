# define-err v0.9.0 - Beta

**The polish pass begins.** v0.9.0 is the first beta: the API is the one planned for 1.0, and the releases from here to 1.0 are for fixing what is left and tuning what is slow. This one re-ran the security review, which found one fault, cut the rebuild time of a plain enum, and gave every requirement a named test or a check in CI.

## What is define-err?

<strong>define-err</strong> is how a Rust library says what its errors are, with no proc macro, no build dependency, and no run-time cost. It is `no_std` and has no dependencies.

```rust
use define_err::define_errors;

define_errors! {
    pub enum PageError {
        NotFound { page: u64 } => "page {page} not found",
        Io(#[from] source: std::io::Error) => "page file i/o failed",
    }
}
```

## What's in 0.9.0

- **One fault found and fixed.** In 0.8.0, `#[code(4294967295, help = "...")]` compiled, and its code read as a placeholder. That number was the stand-in for a code with no number, so it skipped the range check. It is now rejected as out of range, like any other number past the limit.
- **A faster plain enum.** An enum with no namespace and no metadata, whose messages are all plain strings, now expands in one pass over its variants instead of five. The generated code is the same token for token; a 500-variant enum rebuilds 28% faster. The numbers, and why a long variant list cost so much, are in `docs/PERFORMANCE.md`.
- **One error for one mistake.** A malformed `#[category]`, `#[severity]`, `#[kinds]`, `#[public]`, `#[action]`, or `#[retryable]` is reported once; a bad category used to be reported seven times.
- **Every requirement has a test.** `tests/TRACEABILITY.md` maps each requirement to the tests that check it. The gaps it found are filled: 23 new compile-fail cases, a second crate that checks `#[non_exhaustive]` from outside, a property test for `short_file`, and `tools/invariants.py`, which CI runs to check zero dependencies, where `unsafe` may appear, and the size of the source.

No public API changed.

## For the attribute front end

`__private::check_number` no longer skips `INVALID_NUMBER`, and a block calls it only for a `#[code]` whose number is a literal. `docs/GENERATED-CODE.md` has the details.
