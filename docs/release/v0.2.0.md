# define-err v0.2.0 - Design lock

**The public API, written and approved.** v0.2.0 wrote down every public item of define-err 1.0 before any of it was built, and James approved it on 2026-10-29. There is still no functional code in this release; from here the API is locked, and every change to it goes through the decision log.

## What is define-err?

<strong>define-err</strong> is how a Rust library says what its errors are: one `define_errors!` block, one line per variant, and the macro writes the enum, `Debug`, `Display`, `core::error::Error` with `source()`, and the `From` conversions, without a proc macro or a build dependency. Optional attributes add stable error codes with a compile-time catalog, severity, categories that map to HTTP, gRPC, and exit codes, kind masks, public messages, and retry advice; a reporting facade lets any crate report to the application's error service for one atomic load when nothing is installed. It is `no_std` and has no dependencies.

## What's in 0.2.0

- `docs/API.md`: every public item with its signature, behaviour, errors, cost estimate, examples, and the version it arrives in. It covers the `define_errors!` grammar (messages, sources, `transparent`, structs, codes, metadata attributes, every compile error, the limits, and the mapping from thiserror), `ErrorInfo`, codes and namespaces, severity, categories with their HTTP, gRPC, and exit-code tables, kind masks, the code catalog, the identity probe, `Secret<T>`, the reporting facade with its verbs, filters, and events, the owned `ErrorRecord`, and the test capture.
- `docs/GENERATED-CODE.md`: what `define_errors!` expands to, form by form, the format of the identity probe, the compile-time checks, and the hidden `__private` surface with its versioning rule. The attribute front end (`#[derive(Error)]`, a separate crate) builds against this file.
- `tests/golden/`: the packed values of sample codes, sample probe strings, the category tables, the severity names, and the kind bits, written before the code that produces them. The probe builder and the source dispatch were prototyped on Rust 1.81 and matched these files byte for byte.
- Every open decision in the plan was answered. The ones a user will notice:
  - `Option<Code>` is 8 bytes and `Option<Severity>` is 1 byte.
  - The reporting verbs are called by path (`define_err::warn!`) and are not in the prelude, so they never clash with `log::warn!`.
  - A `transparent` wrapper passes on the identity of the error inside it, so a code is never hidden by a wrapper.
  - One error type, `InstallError`, covers both write-once slots (the reporter and the creation hook).
  - No error type echoes rejected input in its message.
- The requests from report-err, the dynamic-error library, were all accepted: `report_record`, `ErrorRecord::new` with `push_chain`, a creation-hook slot for dynamic errors, and the niche in `Code`.

## What's next

`0.3.0` ships the thiserror-parity core: `define_errors!` with messages, sources, `From`, `transparent`, structs, `#[non_exhaustive]` by default, `Debug`, `ErrorInfo` with its defaults, `Location` and `here`, and `Secret<T>`, checked against thiserror's own behaviour and piloted on page-db. `0.4.0` adds codes, metadata, the catalog, and the identity probe; `0.5.0` the reporting facade and the owned record.
