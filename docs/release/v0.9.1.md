# define-err v0.9.1 - Beta

**Two hot paths, faster.** v0.9.1 continues the polish pass. Nothing in the API or in any output changed.

## What is define-err?

<strong>define-err</strong> is how a Rust library says what its errors are, with no proc macro, no build dependency, and no run-time cost. It is `no_std` and has no dependencies.

```rust
use define_err::define_errors;

define_errors! {
    pub enum PageError {
        NotFound { page: u64 } => "page {page} not found",
        Io(#[from] source: std::io::Error) => "page file i/o failed",
    }
}
```

## What's in 0.9.1

- **`Code` shows about 10% faster.** Each letter and digit of `DB-0042` is now worked out on its own, instead of one after another. The text is the same; a new property test checks it against `std` formatting for any code, and so does the fuzz target.
- **The control-character check is four times faster** on a message of a hundred bytes or more. `ErrorRecord` marks a chain message that holds a newline, an escape, or any other control character, so a log sink knows to escape it. The check now reads eight bytes at a time, and a test compares it with `char::is_control` for every Unicode character.
- **The other missed targets, looked at again.** `warn()`, a filtered `report`, and `identify` stay as they are, each for a reason now written down in `dev/PLAN.md` (D-084): making them cheaper would weaken a guarantee or a check.
