# define-err v0.9.3 - Beta

**Faster builds for types with many codes.** v0.9.3 makes the compile-time duplicate-code check scale with n log n instead of the square of the number of codes. The API and the generated code are unchanged, and code that compiled before works the same.

## What is define-err?

<strong>define-err</strong> is how a Rust library says what its errors are, with no proc macro, no build dependency, and no run-time cost. It is `no_std` and has no dependencies.

```rust
use define_err::define_errors;

define_errors! {
    pub enum PageError {
        NotFound { page: u64 } => "page {page} not found",
        Io(#[from] source: std::io::Error) => "page file i/o failed",
    }
}
```

## What's in 0.9.3

- **A faster duplicate-code check.** Every `define_errors!` block with codes runs a `const` check that no two variants share a number. It compared every pair, which at 1,000 codes is half a million comparisons in the compiler's const evaluator. It now sorts the numbers 2,048 at a time and looks the rest up by binary search. A full debug build of one enum of 1,000 variants with codes takes 21.9 s of CPU instead of 24.9; one of 500 takes 8.4 instead of 10.0. The check still rejects the same blocks with the same messages, at the same place.
- **The same generated code.** The macro's output is identical, token for token. Only the body of the internal check function changed, so L2 and anything else that targets `docs/GENERATED-CODE.md` is not affected.
- **A draft of the 1.0 promises.** `docs/STABILITY-1.0.md` lists what 1.x will keep (the API, what generated code does, the code layout and text, the probe format, the category and severity tables, the minimum Rust version, `no_std`) and the test or check that holds each one. It binds nothing before 1.0.
