# define-err v0.9.2 - Beta

**Large enums in any form.** v0.9.2 fixes a compile failure that an enum could hit at a few dozen variants. The API is unchanged, and code that compiled before works the same.

## What is define-err?

<strong>define-err</strong> is how a Rust library says what its errors are, with no proc macro, no build dependency, and no run-time cost. It is `no_std` and has no dependencies.

```rust
use define_err::define_errors;

define_errors! {
    pub enum PageError {
        NotFound { page: u64 } => "page {page} not found",
        Io(#[from] source: std::io::Error) => "page file i/o failed",
    }
}
```

## What's in 0.9.2

- **No more recursion-limit errors on ordinary enums.** An enum not written in the canonical form went through a parser that took a macro step per attribute and chained every variant to the next, so it ran into `recursion_limit` early: at 12 variants with `#[category]` written before `#[code]`, at 32 thiserror-style variants such as `Io(#[from] io::Error)`, and past about a hundred once a single variant was irregular. Enums are now read 32 variants per step, with variant attributes in any order and tuple fields named or unnamed, so 500 variants compile at the default limit. A new test holds an enum of 500 such variants.
- **Large enums with metadata expand faster.** One of 1,000 variants with codes and categories took 6 seconds of compiler time instead of 28; one of 500 took 2.3 instead of 4.1.
- **The same generated code.** The expansion is identical, token for token, on every test, except that unnamed tuple fields are now bound by position (`__define_err_0`, ...) whether or not they carry `#[from]` or `#[source]`. Those names are internal and hygienic.
