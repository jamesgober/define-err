# define-err v0.10.1 - Beta

**New performance figures from a quiet machine.** v0.10.1 continues the pre-1.0 polish pass. It measures every hot path and build time again with the machine to itself, cuts the crate's only unsafe module from five unsafe sites to three, and documents how exit codes follow categories. The API and the generated code are unchanged, and code that compiled on 0.10.0 works the same.

## What is define-err?

<strong>define-err</strong> is how a Rust library says what its errors are, with no proc macro, no build dependency, and no run-time cost. It is `no_std` and has no dependencies.

```rust
use define_err::define_errors;

define_errors! {
    pub enum PageError {
        NotFound { page: u64 } => "page {page} not found",
        Io(#[from] source: std::io::Error) => "page file i/o failed",
    }
}
```

## What's in 0.10.1

- **Measured on a quiet machine.** Every figure since 0.6 was taken while other builds ran. On the quiet machine every hot path is 5% to 50% faster than those figures showed: `Code` `Display` takes 14.3 ns and `warn()` after its first delivery 4.75 ns, so both meet their targets, and a clean build of 20 error enums is 66% faster than with thiserror. Rebuilding one crate after editing a message is 0.03 s slower than with thiserror. The regression baseline is regenerated from this run.
- **A smaller unsafe module.** The write-once slot behind `set_reporter` keeps the value and where it was installed in one cell, so there is one write and one read instead of two of each.
- **Exit codes.** `Category::exit_code` says that only `DataLoss` exits 74 (`EX_IOERR`), and that a program wanting 74 for a failed read or write sets the exit code itself.
