# define-err v0.10.0 - Beta

**Fixes from an independent review.** v0.10.0 closes the findings of an outside review of 0.9.3: outside text can no longer pass for a generated error's identity or reach a record's public message, and a build can hold only one copy of the crate's reporting facade. It is a breaking release; the migration is short and listed below.

## What is define-err?

<strong>define-err</strong> is how a Rust library says what its errors are, with no proc macro, no build dependency, and no run-time cost. It is `no_std` and has no dependencies.

```rust
use define_err::define_errors;

define_errors! {
    pub enum PageError {
        NotFound { page: u64 } => "page {page} not found",
        Io(#[from] source: std::io::Error) => "page file i/o failed",
    }
}
```

## What's in 0.10.0

- **Outside text cannot pass for a generated error.** Generated types answer `identify` through `Error::description()`. On Rust 1.81 to 1.89, std's string errors (`io::Error::other(String)`, `Box<dyn Error>::from(String)`) return their message from `description()` too, so a peer's error text shaped like a probe could claim any code, category, severity, and kinds, and put a sentence of its choosing into `ErrorRecord.public`. Now the probe carries no public message, a record built from `&dyn Error` uses the category's sentence, `identify` refuses an error whose `Display` also begins with the probe's magic (a generated type never does), and `io::Error` is checked before the probe. The CI job on Rust 1.81 runs the test that fails without these. The check costs `identify` about 16 ns on a generated type; a filtered `report` does not make it.
- **One facade per build.** Every 0.x minor version is its own copy of the crate, with its own reporter slot, so a dependency on another line reported into a slot nobody installed. The manifest now sets `links = "define_err_facade"` (with an empty `build.rs`), and Cargo refuses a build with two copies from 0.10 on, naming both.
- **The kinds mask is read whole.** It was stored as two halves, so a verb that ran while the mask changed could filter with half of each and drop an event both masks pass. 64-bit targets now use one atomic; others use a sequence lock that never makes a verb wait.
- **`deprecated(item)` warns once per item.** One call in a loop over a configuration file's keys now reports each deprecated key, not only the first.
- **`catalog::Catalog`.** Several crates' catalogs indexed once, with lookups by binary search and the duplicate-code check built in, for an application or error service that looks codes up across every crate.
- **`would_deliver(severity, kinds)`.** Asks the filters before a caller builds a record that would be dropped.
- **Smaller fixes.** Bidirectional override characters are marked and blanked in a record's one-line `Display`, as control characters are, and a generic type in `define_errors!` gets an error that says generics are not supported.

## Migrating from 0.9

- Move every crate in the build to 0.10 together: Cargo refuses two copies from 0.10 on. Copies from 0.9 and older are not refused; `cargo tree -d -i define-err` lists them.
- `Identity::public` and `Identity::has_public` are gone. Use `err.public_message()` on the typed value, or the `public` field of the code's `CodeInfo`.
- `ErrorRecord::from_error(&err).public` is the category's sentence. To keep a variant's own `#[public]` text, set it from the typed value: `record.public = err.public_message().into()`.
- `deprecated(item)` called with several items from one place now reports each of them once.
