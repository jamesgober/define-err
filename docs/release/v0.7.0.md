# define-err v0.7.0 - Hardening

**Attacked on purpose.** v0.7.0 changes no public API. It writes down every threat to an error library in a service, tests each one with an attack, fuzzes every parser for 24 hours, and runs every verb from 64 threads for 8 hours. The attacks found one defect, fixed here: a panic in an error's own `description()` escaped from `report`.

## What is define-err?

<strong>define-err</strong> is how a Rust library says what its errors are, with no proc macro, no build dependency, and no run-time cost. It is `no_std` and has no dependencies.

```rust
use define_err::define_errors;

define_errors! {
    pub enum PageError {
        NotFound { page: u64 } => "page {page} not found",
        Io(#[from] source: std::io::Error) => "page file i/o failed",
    }
}
```

## What's in 0.7.0

- **A threat model.** `docs/SECURITY.md` lists threats T1 to T17: secrets in messages, forged log lines, memory bombs, floods, hijacked reporters, panics, forged codes, and the rest. Each has its defence, the defence's cost in nanoseconds, and the test that holds it. It also says plainly what is not defended: a code identifies an error, it does not authenticate one, and severity filtering is not a security boundary.
- **An attack test for every threat.** `tests/attack*.rs` try to leak a secret through every format spec, forge every byte of a probe, grow a record past its limits with a cyclic error offering a gigabyte of text, replace the reporter from a dependency, and panic from every place an error's own code runs.
- **A fix.** A reported error's `description()` is its own code, so it may panic. That panic used to unwind into the caller of `report`, `report_with`, or `soft`. It is now caught and counted in `stats().reporter_panics`, like a panic in a reporter. The cost: a filtered `report` takes about 0.4 ns more, and a delivered report of a foreign error about 1.5 ns more.
- **Stress and soak.** `tests/stress.rs` runs every verb from 64 threads with exact counts and memory held flat. Its short pass runs with the suite, and its ten-million-call and 8-hour runs on demand. The 8-hour run made about 99.7 billion verb calls with every count exact, and live memory never passed 22 KB.
- **Fuzzing.** A seventh target, `kinds_display`, and 24 hours on each, from 2.1 billion runs for `kinds_display` and 3.2 billion for the record builder to 23 billion for `Code::parse`. No crash, no leak, no timeout.
- **How it is built, and where it runs.** `docs/ARCHITECTURE.md` walks the modules, the two macro paths, the facade, and the probe. `docs/PLATFORM-NOTES.md` covers what changes by feature and target: atomics, panics, thread-locals, memory, and 32-bit.
