# define-err v0.6.0 - Performance

**Measured, tuned, and published.** v0.6.0 changes no public API. It measures every target in the plan against thiserror, `log`, and error-forge, fixes what fell short, and publishes the rest with the reason. Clean builds of a crate with 20 error enums are 77% faster than with thiserror, the hot paths are several times faster than in 0.5.0, and the path with no reporter installed is one load and a branch.

## What is define-err?

<strong>define-err</strong> is how a Rust library says what its errors are, with no proc macro, no build dependency, and no run-time cost. It is `no_std` and has no dependencies.

```rust
use define_err::define_errors;

define_errors! {
    pub enum PageError {
        NotFound { page: u64 } => "page {page} not found",
        Io(#[from] source: std::io::Error) => "page file i/o failed",
    }
}
```

## What's in 0.6.0

- **Same instructions as hand-written code.** A generated error, the same type under thiserror, and a hand-written one compile to one function: the optimiser merges all three. `Display` is within noise of both.
- **Faster to build.** A plain enum now expands to what `docs/GENERATED-CODE.md` always described, with no method that only repeats a default and no constant to evaluate per variant. A clean build of 20 enums takes 1.2 s against 5.3 s with thiserror, on Linux.
- **The empty path.** With nothing installed, every verb is one load and a branch in the assembly, with nothing set up first. The listing is in `docs/PERFORMANCE.md`.
- **Faster `identify`.** The probe decodes eight digits at a time, in safe code, with the same format and the same validation: 51 ns to 29 ns, and 8 ns to 2 ns for a foreign error.
- **Faster filters.** `report` below the minimum severity reads two digits of the probe, 99 ns to 6 ns.
- **Faster `warn()` and `Code`.** `warn()` after its first delivery went from 41 ns to 16 ns with a new site hash, held to no collision across 234,496 sites. `Code`'s `Display` went from 73 ns to 39 ns with no allocation.
- **Honest numbers.** `benches/floor.rs` measures the fastest of many short batches, because this machine is never quiet; `tools/bench-compare.py` fails a regression over 5%; the build-time script refuses a build that compiled nothing, which is how a false "84% faster" was caught before it reached this page. Benchmarks use the settings an application builds with, not this crate's fat LTO.
- **A fix.** A non-ASCII type or variant name is a compile error, as documented. It compiled, and `identify` then returned `None` for it.

## What fell short

Seven targets are missed, each with its reason in `docs/PERFORMANCE.md` and all of them back on the list for the pre-1.0 polish pass. The one a user will notice: rebuilding one crate after editing a message is slower than with thiserror, by about 0.2 s. A related cost: an enum of 500 variants takes almost twice as long to compile.
