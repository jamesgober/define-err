# define-err v0.4.0 - Codes

**Stable error codes, severity, categories, and a catalog, all as constants.** v0.4.0 adds the metadata a service needs to answer for an error: a code a person can search for (`DB-0001`) with help text, a category that becomes the HTTP status, gRPC code, and exit code, a severity on the OpenTelemetry scale, kind masks, a message safe to show a client, and retry advice. Each is one optional attribute on the variant that needs it.

## What is define-err?

<strong>define-err</strong> is how a Rust library says what its errors are, with no proc macro, no build dependency, and no run-time cost. It is `no_std` and has no dependencies. A reporting facade follows in the next release.

```rust
use define_err::prelude::*;

define_errors! {
    namespace = "DB";
    docs = "https://docs.example.com/errors/{code}";

    pub enum DbError {
        NotFound { page: u64 } => "page {page} not found",

        #[code(1, name = TIMEOUT, help = "Raise pool.size or lower the load.")]
        #[category(DeadlineExceeded)]
        #[public("The database is busy. Try again shortly.")]
        Timeout { after_ms: u64 } => "query timed out after {after_ms} ms",

        #[code(2, help = "Restore the page from a replica, then run a scrub.")]
        #[category(DataLoss)]
        #[severity(CRITICAL)]
        #[kinds(ERROR | SECURITY)]
        Corrupt { page: u64 } => "page {page} failed its checksum",
    }
}

let err = DbError::Timeout { after_ms: 5000 };
assert_eq!(err.code(), Some(DbError::TIMEOUT));
assert_eq!(err.category().http_status(), 504);
assert!(err.is_retryable());
```

## What's in 0.4.0

- **Codes.** A namespace of up to six letters and digits, a number up to 16,777,215, and a display width of 1 to 8 digits (`DB-0001`, `DIS-00001`). `Code` is a `NonZeroU64`, so `Option<Code>` is 8 bytes. `Code::parse` reads the text form back; its error never repeats the input. `name = TIMEOUT` adds an associated constant.
- **A catalog built at compile time.** `DbError::CATALOG` lists every code with its title, help text, category, severity, kinds, public message, docs URL, and state. Deprecated codes name their replacement and warn where their constant is used; `retired = [9, 12]` keeps old numbers from coming back. `catalog::check_unique` checks catalogs from several crates against each other.
- **Categories.** The 16 gRPC canonical codes, each with its HTTP status (Google's published mapping), exit code (`sysexits`), transient flag, AIP-194 retry advice, default severity, default action, and a default public message that names no internal detail. `std::io::Error` maps its kind to a category.
- **Severity and kinds.** OpenTelemetry severity 1 to 24 with the named levels; a 64-bit kind mask with 14 platform bits and 32 for the project.
- **`ErrorInfo` complete**, implemented by every generated type with sensible defaults, so a variant that says nothing still answers.
- **The identity probe.** `identify(&dyn Error)` reads the code, severity, category, kinds, and type name of a generated error behind a trait object; `innermost_code` finds the deepest code in a `source()` chain. Every field is validated, and a foreign error is rejected after one comparison of four bytes.
- **Compile errors, once each.** A duplicate number (rustc marks the second one), a code without help, a namespace or width out of range, a severity outside 1 to 24, a replacement that does not exist, a docs template without a placeholder, an attribute written twice: each is one message at the place it was written, naming the fix. 48 compile-fail tests pin the messages.
- **No cost.** Codes, catalog entries, and probe strings are constants; reading any of them is a `match`, and nothing allocates (a counting allocator checks it).
- **Tested hard.** Golden files freeze code packing, probe strings, category tables, severity names, and kind bits; property tests cover packing, parsing, and probe decoding; five fuzz targets ran clean.
